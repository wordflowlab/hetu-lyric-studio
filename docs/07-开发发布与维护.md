# 开发发布与维护

桌面TXT／LRC交付要求河图0.12.6或更新版本；机器只读分块仍以实际能力发现为准。

Node25、TypeScript、React18、Ajv、esbuild按package-lock固定。npm ci后build、check、test:unit，再用acceptance-lock固定正式宿主执行machine、cross和Electron。SDK与共享色板有来源提交及SHA，构建校验，专业领域不依赖Electron或Cordis。

GitHub保存源码、文档、不可变v0.1.0 Tag、预构建tgz、归档及目录摘要和发行回执。重新下载验证后登记河图插件中心，更新实际工作面、中英指南和博客并核对公网。运行包不能覆盖同版本附件，升级保留旧引用和原操作。研究仓库不进入运行包。

变更先同步领域文档及Schema，再实现和验收。专业字段与规则Owner为02/03和contracts，方法Owner为Skill，完整用例归04，进度唯一Owner为08。修正问题记录首轮失败和条件变化，不提高预算或缩小数据伪造通过。

## 本地验证入口

在仓库根目录使用固定Node25执行：

```bash
npm ci
npm run check
npm run test:unit
npm run package
node scripts/verify-docs.mjs
python3 scripts/fetch-peers.py
python3 scripts/accept-installed.py
```

`accept-installed.py`以`acceptance-lock.json`固定宿主源码、正式归档与插件目录摘要，按machine、cross、ui顺序执行；macOS正式验收需要可用的图形会话。默认安装目标为`/Applications/Hetu.app`且拒绝覆盖未知应用；已有安装由维护者先独立核验，或通过`HETU_ACCEPTANCE_APP`指定隔离目标。输出保留在`output/installed-acceptance`，不把其中的临时授权和原始作品回执提交到GitHub。

| 层次 | 入口与职责 |
| --- | --- |
| 领域单元 | `tests/*.test.ts`，曲式引用、摘要、明确约束、PCM和格式正反例 |
| 正式机器 | `tests/machine.integration.ts`，全部清单动作、固定来源、CAS、原键和生命周期 |
| 专业组合 | `tests/cross.integration.ts`，有声剧实际混音、视听工程和独立小说／剧本 |
| 审核界面 | `tests/ui/workspace.spec.ts`，真实Electron、实际播放、原字节导出、浅暗窄窗与恢复 |

## 不可变发布顺序

1. 运行源码检查与正式安装旅程，保留首轮失败、修正和通过的证据边界。
2. 提交最终源码，固定运行包目录SHA与tgz归档SHA；文档和测试变更不冒充运行包变更。
3. 创建对应版本Tag和GitHub Release，上传预构建tgz、`release-integrity.json`及摘要文件；正式公开附件不覆盖。
4. 从公开下载重新解压，核验归档、目录摘要及每个文件原字节，再用公开包验收。
5. 向河图插件中心登记确切源码、版本、双摘要、最低宿主、实测平台及证据链接；更新中英指南、博客与实际工作面。
6. 部署后核对中英目录、详情、指南、文章及图片的真实响应。失败或未知先读取原发行和安装状态，不换键重复写入。

更新专业领域时同时更新02／03、可执行Schema、CAPABILITIES、包内Skill和04用例。更新宿主公共接口时由宿主Owner同步合同与能力地图，插件不复制宿主实现；更新后重跑受影响旅程，历史引用和同版本附件保持不变。
