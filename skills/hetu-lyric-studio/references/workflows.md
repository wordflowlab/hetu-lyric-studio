# 专业流程

从故事写人物歌时先回读固定人物、情境与已有成果，说明谁在唱、为何唱、希望保留什么意象。Agent准备主歌、副歌或自由曲式，软件不强制套模板。原文范围作为依据，其引文必须匹配固定字节，改编歌词不必复述原文。

已有标记歌词先preview_lyrics，检查未归段、坏标签与未知内容，再import_lyrics。无标签可由Agent提供明确结构，不把空预览当没有歌词。行顺序与段落出场固定；重复副歌建立独立Occurrence。

用rhyme_report核对Unicode字母数字数量、显式音节和韵尾。多音字须明确读音；韵尾相同只表示声明一致，听觉与语义仍需判断。逐句备选固定line_digest，以apply_variant使用；使用后旧读音及音节清空，旧录音和意见可能过期。

外部演唱或作者提交音频后，通过宿主固定asset引用接入Take。先lyric_digest固定歌词，再inspect_take核验真实PCM16、时长与波形。音频格式不符时由外部明确转码，保留原件和来源，不静默伪造WAV。

LRC先preview_lrc，保留原文及转换边界；import_lrc按当前实际编排逐条核对文本和每次副歌。正offset提前显示，最后句终点取实际音频时长。没有真实对齐时只保留未标记状态，不填估计时间。实际播放、定位、听审原话和结构检查分别记录。

返工先读line_digest或take_digest，将意见固定目标摘要；新歌词保留旧Take、Mark、Variant和Note，check_lyrics显示过期。重新对齐须明确处理旧映射，原LRC导入记录只追加。不能把提交新稿自动解释成意见已解决。

导出标记歌词、当前有效LRC、HTML审核本和完整JSON，核对完整与分块摘要。有声剧／视频接续先audio_handoff，再发现下游包Skill与参数，保存并回读专业结果；缺安装说明缺项，不伪造成功。每轮用create_handoff保留固定工程与下一步。
